# Dev Plan

输入是任何方式产出的设计方案：grill 收敛的产物、设计文档、口头描述均可。设计还没收敛到能判"完成"的程度时，先收敛（可走 grill），本流程不做需求澄清。

产物是一份可执行的开发规划：架构、选型、难点、代码量、工期、交付顺序、建议。

## 步骤

1. **复述设计与完成判据**。判据不存在，先向用户要一个——这本身是第一个阻碍。
2. **判定自研与否**。已有成熟开源或服务能覆盖判据时，报二次开发成本作对照；自研仅在现成方案不满足判据时成立。
3. **拆环节，逐环节调研**。对每环节列出技术难点与候选选型。调研要到位才进辩论：外部 API、库版本、平台能力、兼容性不凭记忆，查官方文档或可靠来源；候选一般不少于两个，写清各自取舍。
4. **选型辩论**。一轮抛出当前无依赖未决的全部选型：逐条编号，给推荐和一句话取舍，等用户逐条确认或推翻；用户答完再算下一轮可问的。辩论收敛前不进入估计。
5. **报三笔账与代码量**（口径见下）。
6. **排执行蓝图**：按契约依赖把模块分波次——契约与基础先行，无依赖模块并行散开，集成联调收尾（规则见下节）。
7. **输出规划**。

## 难点与阻碍分类

每个环节标注难点属于哪类，命中的才列：

- **常规**：agent 直接做，不占规划篇幅
- **需 spike**：先写最小验证再定方案（未验证的库、平台行为、性能假设）
- **需人工**：凭据、权限、验收、不可逆操作（删数据、支付、上生产）
- **外部等待**：第三方交付、审批、排期，按人的速度推进，不可压缩
- **上下文不可达**：完成任务需要的代码、文档、数据 agent 拿不到——写明缺什么、谁提供
- **不可判定**：验收标准判不了对错的功能——先要可判定的验收条件，否则工期无界

## 计量：代码量与三笔账

**代码量**：按模块数"必须写的"行数——先扣掉框架、库、起手模板能装走的部分。骨架分钟级即可验证的口径，不拿系统总规模当产出量。

**工期拆三笔账，分开报：**

- **agent 工作时间**：直接估完成时长，不以会话数交差——会话可并行、可压缩续跑，不是时间单位。刻度：骨架分钟级；常规模块 10–60 分钟；带 debug 或联调的耦合模块 1–3 小时。无契约依赖的模块可并行，估时只算关键路径；同一契约上的工作必须串行。总工作量上浮 30–50% 计接洽与返工：上次定的契约下次要重读，会漂移。
- **人工介入点**：需要人做的事，逐个列出，每处一次等待。
- **外部等待**：第三方、审批、采购、排期，单独成行。

墙钟时间约等于 agent 关键路径时长 + 人工介入点 × 人的响应速度 + 外部等待。多数任务里总时长由人的环节决定。

## 多 agent 执行蓝图

- 并行单位是**无共享契约的模块**。同一契约或同一批文件上并行必冲突：先单线把接口、数据模型、协议定死，消费方才散开。
- 一个模块能拆几个 agent，看它内部有几个独立子任务。紧耦合模块强行拆，接洽成本吃掉并行收益。
- 波次之间是集成交界：契约偏差和漂移在交界处暴露，每波收尾留验证步。
- 并行有上限：超过 3–4 路时协调与集成成本反超，无依赖但同文件的模块按文件边界再切。

## 输出

按下面格式产出，每节都要有实质内容；某节为空则写"无"并给一句话原因，不许整节消失：

```markdown
# <项目> 开发规划

## 1. 判据与范围
完成判据（能判对错的验收条件）、明确不做的部分。

## 2. 自研判定
结论；现成方案的二开成本 vs 自研成本的对照。

## 3. 系统架构
模块划分、关键流程、数据模型要点、外部依赖落在哪层。

## 4. 选型表
逐项：已定 | 被否候选 | 一句话理由（辩论收敛后的终态，不列过程）。

## 5. 难点清单
逐环节：难点 | 类别 | 解除方 | 解除动作或 spike 产物。

## 6. 代码量预估
按模块列"必须写的"行数（已扣除框架与库装走的部分）。

## 7. 工期
三笔账分列：agent 工作时间（关键路径时长，注明哪些模块可并行）、人工介入点清单、外部等待清单及量级。收尾给常规效率下的预计完成时间区间，并注明区间的驱动项。

## 8. 交付顺序
分阶段：各阶段范围、依赖、验收关口。

## 9. 多 agent 执行蓝图
模块表：模块 | 依赖 | 可并行 agent 数 | 预计工作量。
波次：每波哪些模块并行、谁先进谁后进、波次间的集成交界。
协作点：契约冻结、跨波次集成验证、验收关口。

## 10. 评估建议
按风险排序：建议砍掉的、建议缓做的、必须先 spike 验证的、可能返工的。

## 11. 需要用户做的事
短清单，只列非用户不可的项，按阻塞顺序排。
```

## 失真自查

写完对照，命中即返工：

- 按软件开发阶段分摊工期（需求一周、开发两周、测试一周）
- 把等待人的环节算进开发工期
- 默认串行：可并行的子任务按串行加总
- 把代码产出量当瓶颈，或把系统总规模当要写的量
- 选型没给候选与取舍，直接默认了最常见的栈
- 报告里只有人日，没有人工介入点
- 用会话数交差而不折成完成时间

## 落盘

选型是"选 A 非 B"的决策，理由会被重新发明的按仓库约定写入 `.harness/notes/`（无 `.harness/` 写 `docs/adr/`）；架构结论持久生效的写 `.harness/spec/`（无则 `ARCHITECTURE.md` 或对应文档）；两者都无则留在对话内。
