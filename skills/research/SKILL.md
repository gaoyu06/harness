# Research

## 上下游

- 后接：选型与工期 → `dev-plan`；界面参考 → `frontend-design`。
- 写入：影响后续决策的结论和来源 → 决策记录；其余 → 会话产物。

## 来源

按可信度排序：

1. 实测结果、源码、官方文档与定价页；
2. 有实名作者的一手经验：issue、个人博客、v2ex 等社区的实践分享；
3. 二手汇总和营销文章。

- 模型型号、价格、版本号、API 用法一律查当前来源。训练数据里的版本可能已经过时。
- 按发布日期筛选：模型、价格和最佳实践默认只用近 6 个月的资料，更早的标注日期。
- 能拿到源码就 clone 到 `/tmp` 读实现。

## 实测

几分钟能验证的结论就实测：调 API 测延迟、首字时间、吞吐和实际计费，跑 benchmark，写最小 demo。实测前估算费用，超过 1 美元或会消耗用户额度时先问。

## 参考竞品

每个参考写清三件事：它怎么做、为什么这样做、我们取哪一点。只借鉴原理和用户所指的那一点，结构、命名和文案自己设计。参考对象本身做得不好的地方，直接指出。

## 输出

- 每条结论附来源链接，或实测命令与输出，并标置信度：实测、官方、一手经验、二手、推断。
- 多个方案对比时编号，给推荐和理由。
- 用户提出与结论矛盾的事实时，先复查来源，再给判断。

## 完成判据

每条结论都有来源或实测记录；没有来源的明确标为推断。
