# 中文文案检查

两遍制：机械抓得住的交给脚本，抓不住的按规则逐条复查。两遍都干净才算通过。

## 第一遍：机械扫描

```
python3 scripts/zh_check.py <file...>
```

脚本输出按规则分组的问题清单：禁用词库命中、模式规则命中、超长句、格式统计。
词库在 `data/banned.json`，按误伤风险分两级：

- `delete`：报告腔式套话——技术、规范文档里不存在合法用法，命中即删
- `context`：人类特定场景会用的词（黑话之于职场、销售腔之于市场文案、自白之于 changelog、高频修饰之于技术写作），命中结合语境判断；每组的 `description` 写明合法情形

发现新词就增补到对应分组，分组本身也可加。

脚本是召回器不是裁判：命中即"可能存在问题的点"，由复查时判断是否真问题。
两个已知误报源——文档在谈论禁用词本身（词库列举、规则说明）属于 mention 而非
use；命中多的规范类文档复核时直接说明即可，不算违规。

## 第二遍：模型逐条复查

脚本查不了的规则，逐条对照原文：

1. **包装词**：脚本词库之外，是否有"能被普通词替换且不损失信息"的词；自造术语是否满足准入三条（无通用词、定义一次多处复用、缺它读不懂系统）
2. **截短词**：是否有被压成单字或半截、且并非比全称更常用的词
3. **拟人**：是否有让系统、规则、工具"知道、觉得、想"的表述
4. **语义重复**：是否两句话讲同一件事、同段重复同一词、对偶两边同义
5. **口语残留**：白话疑问（能不能/该不该）、白话翻译术语
6. **辩解与自白**：是否在解释"为什么没做"，或暴露未完成状态
7. **结构腔**：对偶句、加粗论点列表、戏剧化分节、金句收尾、公允体、隐喻堆叠、文末教训清单是否密集复现（定义见 zh-write「结构腔」）；机械扫描的加粗与破折号计数可作初筛

## 输出

按规则分组报告：规则名 → 行号 → 原文片段 → 建议改法。没有问题的规则不列。

## 边界

- 代码块、报错原文、API 名不算问题
- 对话脚本、语音播报、面向儿童或长辈的文本不适用本检查
