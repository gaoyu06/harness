# 中文写作规范

目标：准确、简洁的书面中文。两类失败模式都要纠正：

| 失败模式 | 例子 |
|---|---|
| 概念包装、AI 腔 | 收口、闭环、赋能、全链路保障、三位一体、亚秒级响应 |
| 口语大白话 | 照样出事、说了算、顶上、免得、丢进队列 |

## 一、用词：只写指称，不写包装

**判断一个词该不该用，看它是"指称"还是"包装"：能被一个普通词替换且不损失信息的词，就是包装词。**

以下三类词都在禁止之列：

- **行业黑话**：闭环、赋能、链路、颗粒度、对齐、拉齐、打法、心智、底层逻辑、方法论、组合拳、护城河、赛道、体感、击穿、联动、沉淀、收口、落地、承载、承接
- **自造词**：现造的术语看似精确，实际要求读者多学一套私人词汇。没有通用词能表达、定义一次多处复用、缺了它就理解不了系统——三条全满足才允许创造并使用；否则用普通词
- **截短词**：AI 常把词压成单字或半截（"都治""待定项"），人很少这样写。缩写仅当它比全称更常用时才可用（API、DB）；否则写全称，或不用缩写

拿不准时把词换成普通词试读：`收口`→`收尾`，`折叠`→`并入`，`承载`→`来自`，`落地`→`实现`。替换后未损失信息，原词就不该出现。

其他命中即改（完整词库按"删除级 / 语境级"分组维护在 zh-check 的 `data/banned.json`，此处为代表性条目）：

- **报告腔套话（删除级）**：奠定了坚实基础、注入新活力、应运而生、有目共睹、值得一提的是
- **高频修饰（语境级，审视是否必要）**：事实上、本质上、换句话说、至关重要、综上所述
- **连接词冗余（语境级）**：此外、另外、首先、其次、与此同时
- **销售腔**：颠覆性、引领、匠心、极致、一站式、全新升级、神器、天花板、遥遥领先
- **模糊信源**：专家认为、据悉、有观点认为——无实名实源时删
- **未完成自白**：尚未、受限于、后续将、目前未实现——对外文档只写已完成事实
- **过度认同**：你说得对、完全同意、确实如您——直接给结果
- **口语残留**：说白了、讲真、搞定、踩坑——换成对应书面词
- **翻译腔**：作为一种、就……而言、对于……来说
- **防御性解释**："之所以不做 X 是因为……"整段删掉；确需留痕一行即可

## 二、句式：书面语、短、不重复

- 疑问用「是否」「能否」，不用「能不能」「该不该」「要不要」
- 主动语态，点明谁做：`系统可自动保存` 不写 `结果将被自动保存`
- 短句为主：`通过……来实现`→`用……实现`，`由于……的原因`→`因为`；以 5–25 字/句为主，长句拆短
- 删虚词不删实词：`进行优化处理`→`优化`；`不/没有/仅/除非`、数字、单位、技术名词绝不删
- 术语照用，不翻成白话：`DB/API/幂等` 原样，不写成「数据库接口」
- 不拟人：主语用系统、规则、逻辑或省略
- 不重复：三个分句讲同一件事压成一句；对偶只在两边信息不同时保留；同段不重复同一词

口语→书面对照：

| 口语 | 书面 |
|---|---|
| 能不能 / 该不该 / 要不要 | 能否 / 是否 |
| 做出来的东西 | 开发成果 |
| 给谁看 | 面向对象 |
| 怎么接进来 | 如何接入 |
| 跑通整个流程 | 完成全流程验证 |
| 接得上 | 即可接入 |
| 派活 | 派发任务 |
| 不需要改动 | 无需改动 |
| 设备不在的时候 | 设备不在时 |
| 没人看着的时候 | 无人留意时 |

## 三、格式节制

- 删装饰性 `**加粗**`、滥用的破折号、标题 Title Case
- 不为填满表格列而造字段，不重复别处已说过的提示
- 每个元素只做一件事：标签标名，示例示范

## 四、不做的不写，不辩解

没要求的功能不加，没做的事不写辩解段落。确需留痕仅一行：`// 未做X：Y已覆盖，触发条件Z时再议`。

## 强度

| 强度 | 触发 | 效果 |
|---|---|---|
| lite | `/zh-write lite` | 去套话与包装词，保留整句与礼貌。对外文档默认 |
| full | `/zh-write` | lite + 压结构、并句、短同义。日常默认 |
| off | `/zh-write off` | 停用 |

## 自动切回完整句式（此时不精简）

- 安全提示、不可逆操作、资金/权限变更
- 顺序敏感的多步操作
- 精简会产生歧义的

## 边界与不适用

- 代码块、报错原文、提交前缀、API 名原样保留
- 落盘文档仅在显式要求时改
- 口语本身即目的的场景不适用：对话脚本、语音播报、面向儿童或长辈的提示

## 自查

- 标题、小节名、表格字段是否出现「能不能」「该不该」「要不要」
- 是否有能被普通词替换的包装词或截短词——新造的术语按第一节准入标准过一遍
- 同段是否重复同一词，或两句话讲同一件事

成稿后可用 zh-check 做一遍机械扫描加规则复查。

## 校准样本

| 不可用 | 应写作 |
|---|---|
| 家里的事，有人管 | 家里的事，可以得到准确传达 |
| 越往下越贴近硬件，动作越快、越不允许出错；越往上越贴近人，变化越快、越允许迭代 | 越底层越贴近硬件，除了快，还要求不出错；上层则主管业务，迭代最频繁 |
| 放在看得见的位置，承担家庭状态的一眼可见 | 放在能被看到的地方，家里的状况，一览无余 |
| 这两阶段开发出来的东西，之后还能不能用 | 这两阶段开发成果是否可以复用 |
| 值得注意的是，该方案通过对底层链路的深度赋能，实现了颗粒度的全面对齐 | 该方案统一了底层链路的粒度 |
| 本方案未引入缓存，主要考虑到当前并发较低……后续如有需要再考虑 | （整段删除）`// 未做缓存：内存存储已满足，QPS>1k 时再议` |
| 对需求进行收口 | 完成需求收尾 |
| 打通业务链路，形成闭环 | 完成整个业务流程 |
| 两个改动都治了重复请求的问题 | 两个改动都解决了重复请求的问题 |
